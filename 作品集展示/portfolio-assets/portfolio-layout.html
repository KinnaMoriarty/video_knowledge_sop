PORTFOLIO CASE STUDY

AI 视频生产 Skill SOP
知识工程系统

将真实案例、视频分析、创作样本与批准产物沉淀为多角色知识库：让 AI 视频生产从一次性 prompt，升级为可复用、可治理、可进化的生产知识系统。

Case-first Knowledge Engineering 六角色 Skill SOP Stage1 / Stage2 治理链路 独立音频分析模块
6角色知识库：制片、编剧、美术、分镜、剪辑、视频制片
2阶段沉淀：案例优先 + RU 分发到方法库
4+核心工作台：学习、音频、项目工程、导出
1统一治理原则：不手写专业 reference 补缺
1

系统流程：从素材到可治理知识库

输入来源参考视频、Artist JSON、Video JSON、approved artifact、音频资产。
前端工作台上传、分析、预览、沉淀、分发、项目方案与音效分析。
后端 API证据归一、case 生成、target map、semantic route、native renderer。
Stage1 / Stage2先进入正式案例库，再从 eligible RU 分发到方法库。
多角色知识库服务后续 Agent 生成、审阅、交接与质量治理。
MODULE 01

知识学习 / 视频分析工作台

从参考视频和剪辑教程中学习可复用知识，前端把分析、案例预览、分类选择和沉淀动作组织成一个统一工作流。

支持参考视频、教程分析、切镜检测与结构化 JSON 预览。
按分类或选中样本组织沉淀范围，避免全量误写。
为 Stage1 case 生成提供经过筛选的来源材料。
MODULE 02

Stage1：案例优先沉淀

系统不把分析结果直接写成规则，而是先生成 public-safe 的正式案例卡，让经验先有来源、场景和边界。

只写入六库 references/cases/*.md 与 CASE_INDEX。
正式 case 禁止 raw JSON、本地路径、debug 字段和 target path。
Producer / Screenwriter 等专业知识必须通过 pipeline 进入库。
MODULE 03

Stage2：RU 分发与知识库治理

Stage2 只读取正式 case 中的 eligible RU，并通过后端固定 target map + semantic route 写入对应角色方法库。

target_file / target_section 不由模型、前端或 case 决定。
先 dry-run 预览，再 apply；section missing 或 broad parent 信号不足会阻断。
cleanup preview 只读，不自动删除或重写正式知识。
MODULE 04

项目工程方案：从 Brief 到多角色产物

在项目工程页中输入 brief，生成 Producer final，并继续推进 Screenwriter、Art Director、Storyboard Artist 等角色产物。

把创意、剧本、美术、分镜从单一 prompt 拆成分阶段产物。
形成 project artifact，后续可作为批准生成物参与知识沉淀。
面向真实生产交付，而不是只输出一次性文本。
MODULE 05

独立音效 / 音频分析模块

音频模块独立于默认 Stage1 / Stage2 主链路，负责上传、分析、预览和同步音效、角色音色与背景音乐资源。

支持 sound_effect、voice_timbre、background_music 三类分析。
提取声音类型、情绪风格、剪辑位置、适配场景和使用建议。
当前作为独立资源分析结果；未来可选进入 case-first 沉淀。

六大角色知识库边界

Producer商业目标、创意策略、主卖点、制作取舍、AI 可行性。
Screenwriter故事主轴、剧本动作、对白字幕、信息释放、连续性。
Art Director视觉目标、资产、风格、prompt-ready 字段、一致性。
Storyboard Artist拆镜、镜头语言、画面 prompt、grid / revision 证据。
Video Editor素材诊断、时间线、切点、声音字幕同步、平台版本。
Video ProducerAI 视频生成执行制片、任务拆分、参考图、prompt、版本和交接。
3

关键产品与工程设计

Case-first 知识工程先沉淀案例，再从案例中抽取可分发知识，避免把一次性观察直接写成通用规则。
RU 协议作为分发入口每条知识都要具备 target、anchor、evidence、method、anti-pattern 和 boundary。
后端固定 target map模型不能决定写入文件和 section，降低跨库污染和错误追加风险。
Dry-run / Apply 分离正式写入前必须预览影响范围、可分发数量、路由结果和阻断原因。
项目价值：把一次性 AI 生成，升级为可持续进化的生产知识系统。 适合展示 AI 产品架构、知识工程、复杂流程建模、多角色 Agent 协同与内容生产工具设计能力。
