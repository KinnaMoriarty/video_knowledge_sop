可以重点考察他这段经历能不能迁移到我们项目的核心问题：**把非结构化内容自动采集、分析、沉淀成可复用的 AI 制片/创意知识与能力模块**。不要只问“会不会用 Cursor/Copilot”，要问他怎么设计数据流、知识结构、验证机制和自动化闭环。

我建议从这几类问。

## 1. 先问项目复盘，看是不是亲手做过

### 问题 1：你那个比特币舆情系统的完整链路是什么？

可以追问：

- 抓取频率怎么定？
- 如何去重？
- 如何处理失败重试？
- 清洗规则是手写的，还是模型辅助的？
- 入库结构怎么设计？
- 实时分析结果怎么被消费？

看点：
 他是否真的做过全链路，而不是只调 API 或写几个爬虫。

------

### 问题 2：如果数据源格式经常变，你怎么保证系统稳定？

结合我们项目可以追问：

> 如果我们的视频案例、剧本、广告素材、创意分析文本来源格式都不稳定，你会怎么设计采集和清洗流程？

看点：

- 有没有 schema 设计意识
- 是否会做容错
- 是否会记录原始数据和处理后数据
- 是否能区分“原始素材”“中间分析”“最终知识沉淀”

## 2. 问他怎么把经验迁移到我们项目

### 问题 3：如果让你做一个“视频案例自动知识沉淀系统”，你会怎么设计？

背景可以这样给他：

> 我们现在希望把优秀广告片、短剧、剧情片案例自动分析，提炼成 Producer 能用的知识，比如角色功能、故事结构、商业创意策略、AI 可实现性等。你会怎么设计从素材到知识库的流程？

重点听他有没有这几个层次：

1. 输入：视频、脚本、字幕、分镜、人工笔记
2. 解析：镜头、角色、剧情、卖点、风格、情绪、品牌信息
3. 结构化：转成统一 schema
4. 审核：人工确认或修改
5. 入库：进入知识库/技能系统
6. 使用：被 Producer Agent 检索和调用
7. 反馈：实际生成效果反哺知识库

这是最贴合我们项目的问题。

------

### 问题 4：如果你要把“金融舆情分析”换成“短视频创意分析”，哪些部分能复用，哪些必须重做？

看点：

能复用的：

- 数据采集
- 清洗
- 去重
- 实时入库
- 自动化 pipeline
- AI 辅助分类和摘要
- 监控和错误处理

必须重做的：

- 领域 schema
- 创意/叙事/制片知识标签体系
- 质量评估标准
- 人工审核流程
- 检索和应用方式

这个问题能看他是否理解“工程能力可迁移，但领域建模要重建”。

------

## 6. 问产品理解和业务迁移

### 问题 11：你觉得金融舆情系统和我们这个 AI 视频/创意知识系统最大的不同是什么？

好的回答应该能说出：

- 金融数据更偏事实、时效、信号
- 创意知识更偏抽象、模式、表达、判断
- 金融分析关注“发生了什么”和“有什么影响”
- 创意分析关注“为什么有效”“能否复用”“如何指导生成”
- 我们的难点不是抓数据，而是把内容转成可执行的创意能力

这是很好的筛选题。

### 问题 12：如果你加入我们，前两周你会先做什么？

看点：

优秀候选人应该不会一上来就说“重构系统”或“全自动化”。比较好的回答是：

1. 先理解现有 Producer 能力结构
2. 看已有知识文档和 draft 流程
3. 跑通现有数据/知识沉淀链路
4. 找一个小领域试点，比如广告片的 commercial creative strategy
5. 做一个从案例输入到结构化知识输出的 MVP
6. 加入人工确认环节
7. 再考虑规模化

他的经历和我们项目有几个匹配点：
